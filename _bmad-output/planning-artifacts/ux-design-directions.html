Argo Workflows Plugin — Design Directions

Design Direction Exploration
Four layout directions for the Argo Workflows Backstage plugin. All use BUI tokens — the difference is how the DAG diagram, workflow list, and node detail panel are arranged. Each direction optimizes for a different priority.

Direction A: Full-Width DAG

DAG takes full content width. Node detail panel slides in as an overlay from the right. Maximizes DAG visibility.

✓ Maximum DAG canvas space — best for large workflows
✓ Topology is the hero
✗ Panel partially obscures DAG when open

Direction B: Split Panel

DAG and node detail panel share the content area side-by-side. Both always fully visible.

✓ DAG and detail always visible simultaneously
✓ Spatial context fully preserved
✗ DAG canvas narrower when panel open

Direction C: Compact Dense

Summary cards + DAG + node detail all on one screen. Optimized for SRE incident response.

✓ All information on one screen — zero scrolling
✓ Optimized for incident response speed
✗ Smaller DAG canvas for large workflows

Direction D: Tekton-Style Expandable Rows

Workflow list with expand button per row. Expanding reveals the DAG inline below the row — same pattern as the Tekton plugin.

✓ Exact same UX pattern as Tekton — familiar to Backstage users
✓ List + DAG in one view, no page navigation
✓ Node status summary dots in the table row
✗ DAG constrained to row expansion area width

Direction E: Expandable Rows + Vertical DAG (D + C hybrid)

Tekton-style expandable rows from D, but the expanded area shows a vertical top-to-bottom DAG with a side panel like C. Combines the best of both patterns.

✓ Tekton-familiar expandable row pattern
✓ Vertical DAG shows true topology with parallel branches side-by-side
✓ Node detail side panel preserves DAG context
✓ No page navigation — list and DAG in one view
✗ Expanded area is taller than horizontal layout

Direction F: Expandable Rows + Horizontal DAG + Side Panel

Tekton-style expandable rows with D's horizontal left-to-right DAG card flow, plus a node detail side panel from E. No summary cards — clean and focused.

✓ Tekton-familiar expandable row pattern
✓ Horizontal DAG fits naturally in expanded row width
✓ Side panel for node detail preserves DAG context
✓ Compact vertical footprint — less scrolling than E
✗ Horizontal scroll needed for very wide workflows

Direction Comparison
Side-by-side evaluation of all four layout directions against our experience principles.
Criterion A: Full-Width B: Split Panel C: Compact D: Tekton-Style E: Expand+Vertical ⭐ F: Expand+Horiz+Panel
DAG canvas size ✓ Maximum ○ Reduced ✗ Smallest ○ Row-width ✓ Full row-width ○ Row-width
Context preservation ○ Panel occludes ✓ Both visible ✓ Both visible ✓ Inline below row ✓ DAG + panel inline ✓ DAG + panel inline
List + DAG in one view ✗ Separate page ✗ Separate page ✗ Separate page ✓ Same view ✓ Same view ✓ Same view
Large workflow comfort ✓ Best ✓ Good ○ Tight ○ Horizontal scroll ✓ Vertical + zoom ○ Horizontal scroll
Incident response speed ○ Need panel ✓ Click → see ✓ Everything visible ✓ Expand → see ✓ Expand → all info ✓ Expand → all info
Tekton plugin familiarity ✗ Different ✗ Different ✗ Different ✓ Same pattern ✓ Same pattern ✓ Same pattern
No page navigation needed ✗ Drill-down ✗ Drill-down ✗ Drill-down ✓ Expand in place ✓ Expand in place ✓ Expand in place
True DAG topology visible ✓ Full graph ✓ Full graph ✓ Full graph ○ Linearized ✓ Full graph ○ Linearized
Summary cards ✗ No ✗ No ✓ Yes ✗ No ✗ No ✗ No
Implementation complexity ○ Overlay ✓ Simple flex ○ Grid ✓ Expandable row ○ Expand + React Flow ✓ Expand + cards
Compact vertical footprint ○ Full page ○ Full page ○ Full page ✓ Compact ○ Tall expanded ✓ Compact
⭐ Direction E: Expandable Rows + Vertical DAG (D + C hybrid)
Combines the best of both worlds. The Tekton-familiar expandable row pattern keeps list and DAG in one view with no page navigation. The vertical top-to-bottom DAG renders true graph topology with parallel branches side-by-side — unlike D's linearized horizontal flow. The node detail panel sits alongside the DAG for context preservation. Handles large workflows with zoom/pan/minimap controls inside the expanded area.
